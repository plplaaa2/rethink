# LG 2RES2VE300UA2 프로토콜 기록

## 문서 범위

이 문서는 한국형 LG 냉장고 `2RES2VE300UA2`에서 직접 캡처한 패킷과 구현 결과를 기록한다.

근거 수준은 다음과 같이 구분한다.

- **확인됨**: 명령 전송과 상태 응답의 왕복 과정에서 재현됨.
- **유력 후보**: 공통 냉장고 레이아웃 및 관찰 결과와 일치하지만, 해당 값만 단독으로 변하는 상황은 확인하지 못함.
- **미확인**: 원시값 또는 가설로만 보존함.

이 기기에서 직접 캡처하지 않은 다른 냉장고 모델의 열거값이나 명령 길이를 그대로 적용하면 안 된다.

## AABB 패킷 구조

패킷 외부 구조는 다음과 같다.

```text
AA 길이 내부-페이로드 체크섬 BB
```

체크섬과 마지막 마커를 우선 0으로 둔 패킷의 모든 바이트를 더한 뒤 하위 1바이트를 취하고, `0x55`와 XOR하여 체크섬을 계산한다.

## Home Assistant 노출 현황

프로토콜 확인 여부와 Home Assistant 노출 여부는 서로 다르다. 패킷에서 확인된 필드라도 의도적으로 엔티티를 만들지 않을 수 있고, 반대로 기기 고유 필드가 아닌 값을 Home Assistant에서 계산하여 엔티티로 제공할 수도 있다.

## F017 설정 명령

기기는 `F017`로 시작하는 실측 캡처 기반 118바이트 명령 본문을 사용한다. 검증된 공통 필드의 명령 바이트 위치는 다음과 같다.

```text
command[2 + statusOffset] = value
```

검증된 설정:

| 상태 오프셋 | 설정            |               꺼짐/값 | 켜짐/값 |
| ----------: | --------------- | --------------------: | ------: |
|           1 | 냉장실 설정온도 |   원시값 = `8 - 섭씨` |       — |
|           2 | 냉동실 설정온도 | 원시값 = `-14 - 섭씨` |       — |
|           3 | 특급 냉동       |                   `1` |     `2` |
|          16 | 특급 냉장       |                   `0` |     `1` |
|          17 | 스마트케어+     |                   `0` |     `1` |

스마트케어+ 켜짐:

```text
AA7CF017FF0000FFFFFFFFFFFFFFFFFFFF00FFFFFF01FFFFFF000000FFFF00FFFFFFFF00FFFFFFFFFFFFFFFFFF00FFFFFF1EFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFF0AFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFF00FFFFFFFFFFFFFFFFFFFFFFFFFFFFFFB8BB
```

스마트케어+ 꺼짐:

```text
AA7CF017FF0000FFFFFFFFFFFFFFFFFFFF00FFFFFF00FFFFFF000000FFFF00FFFFFFFF00FFFFFFFFFFFFFFFFFF00FFFFFF1EFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFF0AFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFF00FFFFFFFFFFFFFFFFFFFFFFFFFFFFFFB9BB
```

공통 ACK:

```text
AA08100017008CBB
```

ACK는 명령이 수신·처리됐다는 뜻일 뿐 실제 상태 변경을 보장하지 않는다. 기기가 동작 중일 때 스마트케어+ 끄기 명령이 ACK를 받았지만 상태가 바뀌지 않은 사례가 있었다. 실제 상태는 `10EB/10EC status[17]`을 기준으로 판단한다.

## F010 야간 눈부심 방지 설정

현재 확인된 페이로드 구조:

```text
F0 10
02
mode
YY MM DD HH MM SS   시작, UTC
YY MM DD HH MM SS   종료, UTC
00                  예약 필드
brightness          정수 백분율을 1바이트에 직접 인코딩
```

모드:

```text
01 = 일출/일몰 일정
02 = 사용자 지정시간 일정
```

관찰된 지원 밝기:

```text
0, 10, 30, 50, 80, 100
```

사용자 지정시간 예시, KST 21:00-06:00 및 밝기 30%:

```text
AA16F01002021A080E0C00001A080E150000001E36BB
```

시간은 UTC로 인코딩해야 한다. 현지 시간으로 다음 날 종료되는 일정도 UTC 변환 결과에 따라 시작과 종료 날짜가 같은 UTC 달력 날짜일 수 있다.

일출/일몰 및 밝기 30% 예시:

```text
AA16F01002011A080E0A2F111A080E142F00001E9BBB
```

ACK:

```text
AA081000100087BB
```

68바이트 상태 레코드에서는 오프셋 30으로 모드를 확인할 수 있지만, 설정한 밝기를 보여주는 오프셋은 확인되지 않았다.

## 에너지 관련 보고

관찰 예시:

```text
AA0910AF0F001DCBBB   하위 유형 0F, 값 29
AA0910AF0F0021F7BB   하위 유형 0F, 값 33
AA0910AF10005A89BB   하위 유형 10, 값 90
```

페이로드의 마지막 2바이트는 부호 없는 빅엔디언 숫자로 해석한다. 동일한 보고가 몇 초 안에 여러 번 재전송될 수 있다.

아직 확인되지 않은 사항:

- 값이 Wh인지, 현재 구간의 카운터인지, 다른 에너지 단위인지.
- 하위 유형 `0F`/`10`이 기간, 보고 종류, 순번 중 무엇을 의미하는지.
- 실제 보고 및 초기화 경계.
- 신뢰할 수 있는 순간 소비전력(W)을 계산할 수 있는지.

현재 Home Assistant 구현의 15분 호환 구간은 빠르게 반복되는 패킷의 중복 누적을 막기 위해서만 사용한다. **이는 구현상의 가정이며 기기 보고 주기가 15분으로 확인됐다는 뜻이 아니다.** 시간·일·월·총 누적값은 소프트웨어가 관리하며, 기기가 직접 제공하는 누적값으로 확인되지 않았다.

## Home Assistant 소프트웨어 계산값

다음 값은 기기의 고유 총 누적 카운터를 읽는 것이 아니라 로컬에서 계산한다.

- 오늘 도어 개방 횟수.
- 오늘 도어 개방 시간.
- 현재 시간, 오늘, 이번 달 및 총 누적 에너지.

애드온의 영구 데이터를 삭제하면 소프트웨어가 유지하던 총 누적 기준값도 초기화된다.

## 다음 검증 대상

1. LG 앱에서 냉장실과 냉동실 각각 “온도가 잘 유지되고 있어요”와 “설정온도보다 온도가 높아졌어요”가 표시될 때 `10EB`를 캡처한다.
2. 위 두 앱 문구에 따라 오프셋 27과 28이 서로 독립적으로 변하는지 확인한다.
3. 기기의 표시창 잠금을 직접 전환하고 `10EC`를 캡처하여 오프셋 10의 잠금/해제 극성을 확인한다.
4. 이 모델에서 Pure N Fresh 꺼짐/자동/파워 전환 패킷을 캡처한다.
5. 여러 시간 및 정각 경계에 걸쳐 서로 다른 `10AF` 값과 타임스탬프를 기록한다.
6. 안전한 냉장고 재시작부터 설정온도 복구까지의 모든 트래픽을 캡처한다.
